## 3. Выбор БД и сценарии

| Сервис                     | Сценарий использования                               | Тип БД                             | Обоснование                               |
| -------------------------- | ---------------------------------------------------- | ---------------------------------- | ----------------------------------------- |
| Облачный сервис видео      | Хранение записей видео (объекты), метаданные событий |                                    |                                           |
| — Видео                    | Объектное хранилище S3‑совместимое                   | Объёмы терабайты, потоковые записи |                                           |
| — Метаданные (время, ID)   | Быстрые вставки и запросы по времени/устройству      | PostgreSQL                         | ACID, индексы по времени и устройству     |
| Сервис уведомлений         | Очередь событий и статус доставки                    | Redis Streams / Kafka              | Высокая пропускная способность, retention |
| Сервис аутентификации      | Хранение пользователей, токенов                      | PostgreSQL                         | Надёжность, сложные транзакции            |
| Сервис настроек устройства | Конфигурации устройств (редко меняются)              | MongoDB                            | Гибкая схема, вложенные структуры         |
| Мобильное приложение (кэш) | Быстрые чтения последних событий                     | Redis                              | In-memory, низкая задержка                |

### Сценарий выбора

* **Объектное хранилище** для видео: оптимизировано под большие бинарные файлы.
* **PostgreSQL** для метаданных: нужна транзакционная целостность, сложные запросы.
* **Redis Streams/Kafka**: распределённая очередь для масштабирования уведомлений.
* **MongoDB**: удобен для хранения JSON-конфигов без жёсткой схемы.
* **Redis (in-memory)**: кэш последних событий для мгновенного отображения клиенту.

<a name="репликация-шардинг"></a>

## 4. Репликация и шардинг

### Репликация

* **PostgreSQL:** мастер-слейв реплики для чтения (read replicas) на региональных нодах. Обеспечивает отказоустойчивость и балансировку чтения.
* **MongoDB:** Replica Set с тремя нодами (1 primary, 2 secondary) для отказоустойчивости.
* **Redis:** Redis Cluster с мастерами и репликами, автоматическое переключение.

### Шардинг

* **PostgreSQL:** шардинг по времени и ID устройства с помощью Citus (расширение) или логической шардировкой.
* **Kafka:** партиционирование топиков по ключу (device\_id) – гарантирует упорядоченность.
* **MongoDB:** шардинг коллекции configs по \_id или device\_id для горизонтального масштабирования.
