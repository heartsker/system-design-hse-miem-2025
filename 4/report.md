## 1. Функциональные и нефункциональные требования

**Функциональные (ФТ):**

* Уведомление о нажатии кнопки с возможностью ответа через приложение.
* Двусторонняя аудиосвязь и видеостриминг в реальном времени.
* Обнаружение движения и автоматическая запись видео.
* Переключение в режим Wi-Fi точки доступа для первой настройки устройства.
* Управление устройством и просмотр стримов через мобильное приложение.

**Нефункциональные (НФТ):**

* **Производительность:** задержка аудио/видео ≤ 500 мс.
* **Доступность:** 99.9% uptime для облачных сервисов.
* **Масштабируемость:** поддержка до 100 000 устройств, пиковый видео-трафик \~20 Гбит/с.
* **Безопасность:**  TLS для стриминга и REST, AES‑256 для хранения; аутентификация OAuth2.0.
* **Юридические требования:** хранение пользовательских данных в РФ (ФЗ‑152).
* **Ограничения устройства:** 512 МБ ОЗУ, 4 ГБ ПЗУ.

## 2. Сервисы и интеграции между ними

### Сервисы:

1. **Устройство DingDong (Hardware)**

   * Сбор аудио/видео, кнопка, Wi-Fi модуль.
2. **Облачный сервис видеообработки**

   * Прием RTSP/WebRTC, детекция движения, хранение записей.
3. **Сервис уведомлений**

   * Обработка и доставка push и вебсокет-уведомлений.
4. **Сервис аутентификации и авторизации**

   * OAuth2.0, управление токенами.
5. **Сервис управления настройками устройства**

   * REST API для конфигурации через Wi-Fi точку доступа.
6. **Мобильное приложение (Frontend-клиент)**

   * UI для стриминга, уведомлений, настройки и управления.
7. **Хранилище и база данных**

   * Объектное хранилище для видео (S3‑совместимое) и реляционная БД для метаданных.

### Интеграции:

| Отправитель                           | Получатель                          | Тип связи   | Протокол/Технология  | Примечание                          |
| ------------------------------------- | ----------------------------------- | ----------- | -------------------- | ----------------------------------- |
| Устройство ⇢ Облачный сервис видео    | Видеообработка                      | Синхронная  | RTSP или WebRTC      | Для низкой задержки стрима          |
| Видеообработка ⇢ Сервис уведомлений   | Уведомления                         | Асинхронная | RabbitMQ (или Kafka) | Сообщения о движении, нажатии       |
| Мобильный клиент ⇄ Сервис Auth        | Аутентификация/Авторизация          | Синхронная  | REST + OAuth2.0      | Получение access/refresh токенов    |
| Сервис уведомлений ⇢ Мобильный клиент | Клиент уведомления                  | Асинхронная | WebSocket (или FCM)  | Push и live-уведомления             |
| Мобильный клиент ⇄ Сервис настроек    | Управление конфигурацией устройства | Синхронная  | REST API             | Изменение пароля, Wi-Fi SSID, др.   |
| Устройство ⇄ Сервис настроек          | Локальная настройка через Wi-Fi     | Синхронная  | HTTP REST (локально) | Прямая связь в режиме AP            |
| Видеообработка ⇄ Хранилище            | Сохранение видео и метаданных       | Синхронная  | S3 API + SQL         | Объектное хранилище и БД метаданных |

<a name="обоснование"></a>

## 3. Выбор способов взаимодействия и обоснование

1. **RTSP/WebRTC для видео**

   * **Задача:** минимизировать задержку (<500 мс).
   * **Обоснование:** WebRTC оптимизирован под P2P стриминг с NAT traversal; RTSP проще в реализации на устройстве.

2. **Асинхронные очереди (RabbitMQ/Kafka)**

   * **Задача:** доставка событий (движение, нажатие кнопки) без блокировки основного потока.
   * **Обоснование:** очереди позволяют буферизовать пиковые нагрузки и масштабировать обработку.

3. **REST + OAuth2.0 для авторизации и управления**

   * **Задача:** безопасный доступ к API.
   * **Обоснование:** REST широко распространен, легко интегрируется с мобильными SDK; OAuth2.0 стандарт для токенов.

4. **WebSocket (или FCM) для уведомлений**

   * **Задача:** доставить push и live-события пользователю.
   * **Обоснование:** вебсокеты обеспечивают двусторонний канал; FCM упрощает пуш на Android/iOS.

5. **Локальный REST для настройки устройства**

   * **Задача:** конфигурировать SSID, пароль и прочие параметры при первом подключении.
   * **Обоснование:** прямой HTTP без облака упрощает UX установки и повышает надежность.

6. **S3 API + SQL**

   * **Задача:** хранение больших объектов (видео) и структурированных данных (метаданные).
   * **Обоснование:** разделение хранилищ оптимизирует стоимость и производительность.

<a name="hld"></a>

## 4. Верхнеуровневая схема (HLD)

```plaintext
+----------------+                      +----------------------------+
| Устройство     | ---(RTSP/WebRTC)---> | Облачный сервис видео      |
| DingDong       |                      | - детекция движения        |
+----------------+                      | - запись, хранение         |
         |                               +-----------+----------------+
         |                                           |
         |                                           |-(очередь)-->+
         |                                           |             |
         |                                           v             |
         |                                      +---------------+  |   +--------------+
         |                                      | Сервис        |  |   | Сервис       |
         | ----------(REST локально)----------> | уведомлений   |--+-->| аутентиф./   |
         |                                      +---------------+  |   | авторизации  |
         |                                                         |   +--------------+
         |                                                         |
         |                                                         |   +----------------+
         |                                                         |   | БД метаданных   |
         |                                                         +-->| + S3-хранилище  |
         |                                                         |
         +--(Wi-Fi AP REST)--> [Сервис управления настройками] <---+

Мобильный клиент:
- REST/OAuth2 → сервис авторизации
- REST → сервис настроек
- WebSocket/Firebase → сервис уведомлений
- HLS/WS → облачный сервис видео (для просмотра)
```
